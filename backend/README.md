# Siembra Satelital API (backend)

Small stateless Node.js API that compares **3 crop rotation strategies** for a farm in El Salvador's Dry Corridor using precomputed NASA data and transparent scoring rules. No database, no auth, no npm dependencies.

## Quick start

```bash
cd backend
cp .env.example .env      # Windows: copy .env.example .env
npm run dev               # http://localhost:3001/api  (auto-reload)
npm test                  # unit + HTTP tests (node:test)
```

Requires Node.js >= 20.12. `npm install` is not needed (zero dependencies).

## Endpoints

| Method | Path | Description |
| --- | --- | --- |
| GET | `/api/health` | Status, data version and integration config (LLM, NASA POWER) |
| GET | `/api/zones` | Pilot zones (id, name, lat/lon, data gaps) |
| GET | `/api/zones/:id/climate` | Monthly rain, soil moisture, max temp, NDVI, indicators, sources, glossary. Add `?live=true` to refresh from the NASA POWER API (falls back to cached data) |
| GET | `/api/crops` | Current crop systems, priorities, scenario limits and crop traits table (for the form) |
| POST | `/api/recommend` | Runs the scoring engine and returns rotations A/B/C with scores, evidence, benefits, risks, gaps, confidence and disclaimer |
| POST | `/api/explain` | Plain-English explanation (max 80 words) per rotation. Uses the LLM if `LLM_API_KEY` is set, otherwise templates |

### Request body (`/api/recommend` and `/api/explain`)

```json
{
  "zoneId": "chalatenango",
  "currentCrop": "maize-bean",
  "priority": "save-water",
  "constraints": { "irrigation": false, "avoidCrops": ["cassava"] },
  "scenario": { "rainfallChangePct": -20, "temperatureChangeC": 1 },
  "strategyId": "B"
}
```

- `zoneId`: `chalatenango` | `morazan` | `la-union` (see `GET /api/zones`)
- `currentCrop`: `maize-bean` | `coffee` | `vegetables` (see `GET /api/crops`)
- `priority`: `save-water` | `extra-income` | `improve-soil`
- `constraints`, `scenario`: optional. `scenario` powers the what-if slider (rain -50..30 %, temperature 0..4 °C)
- `strategyId`: optional, `/api/explain` only (`A`, `B` or `C`)

Errors follow `{ "error": { "code", "message", "details?" } }` with status 400/404/405/500.

### Response shape (`/api/recommend`, abridged)

```json
{
  "zone": { "id": "chalatenango", "name": "Chalatenango" },
  "weights": { "water": 0.4, "soil": 0.15, "erosion": 0.15, "income": 0.15, "risk": 0.15 },
  "indicators": { "annualRain": { "value": 1444, "unit": "mm/year", "source": "NASA POWER PRECTOTCORR" } },
  "rotations": [
    {
      "id": "B", "name": "Maize + bean + Jack bean cover", "total": 0.765, "rank": 1,
      "whySuggested": "...",
      "scores": { "water": { "score": 0.718, "reason": "...", "evidence": [ { "label": "...", "value": 1444, "source": "NASA POWER ..." } ] } },
      "benefits": ["..."], "risks": ["..."], "dataGaps": ["..."], "humanValidation": ["..."]
    }
  ],
  "ranking": { "order": ["B", "C", "A"], "best": "B", "similar": false, "message": "..." },
  "confidence": { "level": "medium", "reasons": ["..."] },
  "dataGaps": [ { "key": "soil_type" }, { "key": "market_prices" }, { "key": "pests" } ],
  "disclaimer": "This tool supports your decision; it does not replace ..."
}
```

## How the scoring works

1. `src/scoring/indicators.js` reads the zone summary and applies the optional scenario (less rain, more heat) to get water stress and heat stress indexes.
2. `src/rotations/buildRotations.js` always builds 3 strategies from `data/crops.json`:
   - **A** the current rotation
   - **B** the current rotation + the best cover crop or legume for the bare-field window
   - **C** the most water-demanding crop replaced by (or the plot diversified with) a drought-tolerant crop
3. `src/scoring/engine.js` scores each rotation from 0 to 1 on `water`, `soil`, `erosion`, `income` and `risk`. Every score keeps the NASA indicators that produced it (`evidence`).
4. `total = sum(weight * score)`. The chosen priority gets weight 0.4 and the other dimensions share the rest (`src/scoring/weights.js`).
5. `src/scoring/confidence.js`: high rainfall variability lowers confidence; if the top 2 options are less than 0.05 apart they are reported as **similar** instead of forcing a winner.
6. The LLM (`src/explain`) only receives the evidence JSON and rewrites it in plain English (max 80 words). If it fails or is not configured, templates are used.

## Data

| File | Content |
| --- | --- |
| `data/zones.json` | Pilot zones (each in a different NASA POWER grid cell) |
| `data/climate_summary.json` | Monthly series + indicators per zone, generated by the preprocessing scripts |
| `data/crops.json` | Crop traits table and strategy candidates. **To validate with a local technician** |

Rebuild the NASA data (Python 3.10+):

```bash
pip install -r scripts/preprocess/requirements.txt
npm run data:power    # NASA POWER daily 2014-2023 -> data/raw/power_<zone>.json
npm run data:ndvi     # MODIS NDVI via ORNL DAAC (no login, slow) -> data/raw/ndvi_<zone>.json
npm run data:build    # -> data/climate_summary.json
```

Without NDVI, the bare-field window is estimated from months with < 50 mm of rain and listed as a data gap. Soil moisture currently comes from NASA POWER `GWETROOT`; SMAP is listed as pending. `python scripts/preprocess/fetch_earthdata.py --search-granules` lists SMAP / GPM IMERG granules with `earthaccess` (needs `EARTHDATA_USERNAME` / `EARTHDATA_PASSWORD`).

## Environment variables

See `.env.example`. All are optional: the API works offline with the precomputed JSON and templates.

| Variable | Default | Purpose |
| --- | --- | --- |
| `PORT` | `3001` | Local dev server port |
| `CORS_ORIGIN` | `*` | Allowed frontend origins (comma separated) |
| `LLM_API_KEY` | empty | Enables LLM explanations (OpenAI-compatible API) |
| `LLM_BASE_URL` | `https://api.openai.com/v1` | Any OpenAI-compatible Chat Completions endpoint |
| `LLM_MODEL` | `gpt-4o-mini` | Model name |
| `LLM_TIMEOUT_MS` | `8000` | After this the template fallback is used |
| `NASA_POWER_LIVE` | `true` | Allow `?live=true` on the climate endpoint |
| `NASA_POWER_BASE_URL` | `https://power.larc.nasa.gov/api` | NASA POWER API base URL |
| `NASA_POWER_TIMEOUT_MS` | `8000` | After this the cached data is used |

## Deploy (Vercel)

Each file in `api/` is a Vercel serverless function (same routes as local; `src/server.js` emulates Vercel routing for local dev). Create a Vercel project with **Root Directory = `backend`**, no build command, and set the env vars above (`CORS_ORIGIN` = your frontend URL, `LLM_API_KEY` if used).

## Structure

```
backend/
  api/                  Vercel functions = HTTP routes
  data/                 zones, climate summary, crop traits (JSON)
  scripts/preprocess/   Python scripts that download and summarize NASA data
  src/
    data/               JSON loaders + NASA POWER live client
    explain/            LLM client, prompt, templates, explain service
    lib/                HTTP helpers (CORS, errors, JSON body) and input validation
    rotations/          builds strategies A, B, C
    scoring/            indicators, weights, engine, confidence/ties
    server.js           local dev server
  tests/                node:test suite
```
